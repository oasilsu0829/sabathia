# 잡지 편집 로직 (심층 기사용)

음악 잡지 4권(Drop · feedback · Cypher · 33⅓)의 기사를 Claude가 직접 쓰는 방식의 설계.
목표는 "그럴듯한 글"이 아니라 **취재한 사실 위에 일관된 시각으로 쓴 깊은 글**이다.
편집부 성격은 `personas.md`, 화면은 `stitch-prompts.md`.

---

## 0. 원칙

1. **Claude는 음악을 듣지 못한다.** 그래서 사실과 판단을 나눈다.
   - 사실: 출처가 있어야 쓴다(발매일, 크레딧, 녹음 과정, 아티스트 발언, 평단 반응).
   - 해석: 사실 두 개 이상을 이어서 끌어낸 것. 근거 사실을 가리켜야 한다.
   - 의견: 편집부 성격이 내리는 판단. 근거가 된 해석을 가리켜야 한다.
2. **소리 묘사는 증언으로만.** "기타가 날카롭다" 같은 문장은 출처 두 곳 이상이 같은 말을 할 때만 쓴다. 한 곳뿐이면 "~라고 프로듀서는 말했다"처럼 출처를 밝힌다.
3. **지어내지 않는다.** 기록에 없는 숫자·순위·인용·일화는 쓰지 않는다. 모자라면 분량을 줄인다.
4. **가사 인용 0줄.** 다른 매체 문장도 옮기지 않는다(직접 인용은 아티스트 발언 한 문장, 출처와 함께만).
5. **성격은 시각이지 거짓말 면허가 아니다.** 깐깐한 평론가도 사실은 똑같이 지킨다.

## 1. 재료 (데이터 계층)

| 층 | 무엇 | 어디서 | 언제 |
|---|---|---|---|
| 신보 목록 | 그 주 앨범, 장르별 | Spotify 검색 `tag:new` + 장르 필터 (Worker, Client Credentials) | 월·수·금 0시(KST) cron |
| 앨범 기본 | 트랙·길이·레이블·℗ 표기·발매일·트랙 아티스트(피처링) | Spotify `/albums/{id}` | cron |
| 아티스트 경력 | 지난 앨범 목록과 날짜, 장르, 사진 | Spotify `/artists/{id}`, `/albums` | cron |
| 크레딧 | 프로듀서·엔지니어·연주자·녹음 장소 | MusicBrainz API(무료, 키 없음, 초당 1회), 레이블 보도자료 | 편집 세션 |
| 배경 | 인터뷰, 녹음 과정, 앨범 소개 | 웹 검색 (매체 기사, 위키백과, 아티스트 SNS 공지) | 편집 세션 |
| 평단 반응 | 다른 매체의 평가 경향 | 웹 검색 (요약만, 문장 옮기기 금지) | 편집 세션 |
| 샘플 원곡 | 힙합 샘플·인터폴레이션 | 웹 검색 (크레딧 표기, 샘플 데이터베이스) | Cypher 편집 세션 |
| 내 청취 | 재생 기록, 크레이트 들은 횟수 `p`, 독자 점수 | 앱이 올린 기록 (D1) | 매달 1일 |
| 편집부 기억 | 지난 호 기사·점수·쓴 비유·예고 | D1 `mag_archive` | 매 호 |

cron은 재료만 모은다. 글은 편집 세션(Claude 예약 작업)이 쓴다.

## 2. 한 호를 만드는 순서

한 호 = Claude 세션 하나. 단계마다 결과를 `/api/mag/drafts/<호 id>/<단계>`에 저장해서, 세션이 끊겨도 다음 세션이 이어 받는다.

### 2-1. 편성 회의
후보 앨범마다 점수를 매겨 지면을 나눈다.

```
편성점수 = 0.30 × 내 관련도      (내가 들은 아티스트·크레이트에 있는 아티스트·같은 장르를 자주 들음)
         + 0.25 × 화제성        (웹 검색 결과 수, 다룬 매체 수)
         + 0.25 × 취재 가능성   (1차 취재에서 찾은 출처 수)
         + 0.20 × 편집부 적합도 (성격의 취향 목록과 맞는가, 반대로 '반박할 거리'가 있는가)
```

- 이미 다룬 앨범은 뺀다(같은 아티스트는 3호 안에 다시 메인으로 쓰지 않음).
- 결과: 메인 1 (필청 또는 커버 스토리) · 리뷰 2~3 · 단평 4~6 · 특집 주제 1.
- **특집 주제 찾기**: 이번 주 후보들 사이 공통점(같은 프로듀서, 같은 샘플, 같은 장르 흐름, 같은 날 나온 라이벌)을 찾고, 2개 이상 엮이면 특집으로 쓴다.

### 2-2. 취재
앨범마다 **취재 노트**를 만든다.

```json
{
  "album": "spotify:album:...",
  "facts": [
    { "id": "f1", "claim": "프로듀서는 ○○", "kind": "credit", "src": "https://...", "conf": "high" },
    { "id": "f2", "claim": "녹음은 6주, 시골 농장 스튜디오", "kind": "process", "src": "https://...", "conf": "med" }
  ],
  "sound": [
    { "claim": "드럼을 거의 안 쓴 앨범", "srcs": ["https://a", "https://b"] }
  ],
  "said": [ { "who": "아티스트", "gist": "이번엔 라이브 한 번에 녹음하고 싶었다", "src": "https://..." } ],
  "reception": { "summary": "대체로 호평, 길이 지적 다수", "srcs": ["..."] },
  "career": { "prev": ["전작 (2022)", "전전작 (2019)"], "change": "전작보다 소리가 작아짐" },
  "samples": [ { "track": "곡", "from": "원곡 — 아티스트 (연도)", "src": "..." } ],
  "gaps": ["녹음 장소 미확인"]
}
```

- 출처 하한: 메인 리뷰 5곳 이상(서로 다른 곳), 리뷰 3곳, 단평 2곳. 못 채우면 한 단계 내린다(메인 → 리뷰 → 단평 → 제외).
- `kind`: credit · release · process · said · reception · chart · sample.
- `conf`: high(공식·1차 출처) · med(믿을 만한 매체) · low(커뮤니티). low만 있는 사실은 쓰지 않는다.
- 검색 예산: 메인 15회, 리뷰 8회, 단평 3회. 넘으면 있는 재료로 쓴다.

### 2-3. 논점 잡기
글마다 쓰기 전에 **설계도**를 만든다.

```json
{
  "thesis": "한 문장 주장",
  "because": [ { "point": "근거 1", "facts": ["f1", "f3"] }, { "point": "근거 2", "facts": ["f2"] }, { "point": "근거 3", "facts": ["s1"] } ],
  "counter": "가장 강한 반론과 그에 대한 편집부 답",
  "context": "전작·장르·같은 주 다른 앨범과의 관계",
  "moments": ["짚을 곡 2~3개와 이유"],
  "verdict": "결론 한 줄",
  "lens": "성격별 질문에 대한 답 (personas.md의 '보는 눈')"
}
```

- 근거 3개가 사실에 연결되지 않으면 쓰지 않는다.
- 반론을 반드시 하나 다룬다(심층 글과 감상문의 차이).

### 2-4. 점수
성격마다 기준별 하위 점수 → 가중 합 → 성격 보정.

| 잡지 | 하위 기준 (가중) | 보정 |
|---|---|---|
| Drop (0.0~10.0) | 앨범 완결성 30 · 곡 25 · 소리·연주 20 · 길이 절제 15 · 오래 남을까 10 | 최근 20개 평균이 6.0~6.9에서 벗어나면 반대로 0.1~0.3 당김. 8.0 이상은 최근 10개 중 1개까지 |
| feedback (볼륨 1~11) | 밴드 합 30 · 장면을 만드는 힘 30 · 진심 20 · 새로움 20 | 신인은 +1 너그럽게. 11은 한 해 한 번 |
| Cypher (별 0.5~5) | 가사·주제 30 · 랩 25 · 프로덕션 25 · 앨범 완성도 20 | 3.0 = 잘 만든 앨범. 4.5 이상은 장르사에 남을 판 |
| 33⅓ | 점수 없음 (순위) | — |

- 점수 근거 메모(하위 점수와 한 줄 이유)를 함께 저장. 화면에서 "점수 근거" 펼치기로 보인다.
- **필진 장부**: 평론가마다 지난 점수를 기억한다. 같은 아티스트 전작 점수가 있으면 글 안에서 그 차이를 설명해야 한다("이 지면은 전작에 6.4를 줬다. 이번엔…").

### 2-5. 초고
성격별 글 뼈대(personas.md) + 설계도로 쓴다. 분량 목표:

| 글 | 분량 |
|---|---|
| 메인 리뷰 / 커버 스토리 | 2,000~3,500자 |
| 리뷰 | 1,000~1,500자 |
| 단평 | 250~400자 |
| 특집 | 1,500~2,500자 |

글 안 블록: 리드 문단 · 본문 · 풀쿼트(편집부 자신의 문장) · 팩트 박스(발매·레이블·프로듀서·길이) · 트랙별 짧은 메모(메인만) · 점수 박스 · 출처.

### 2-6. 데스크 검수 (따로 한 번 더)
초고를 쓴 뒤, 같은 세션에서 **검수자 역할로** 다시 읽는다. 고친 내역은 `desk.json`에 남긴다.

1. **사실 대조**: 문장의 고유명사·숫자·날짜를 모두 취재 노트와 맞춘다. 노트에 없으면 지운다.
2. **소리 검사**: 소리를 묘사한 문장마다 `sound`의 출처가 있는가. 없으면 지우거나 출처를 밝힌 문장으로 바꾼다.
3. **베끼기 검사**: 참고한 기사 문장과 연속 8어절 이상 겹치면 다시 쓴다.
4. **가사 검사**: 가사로 보이는 따옴표 구절이 있으면 지운다.
5. **말투 검사**: 성격의 금지어·클리셰 목록, 지난 4호에 쓴 비유 반복(편집부 기억과 대조).
6. **반론 검사**: 반론 문단이 있는가.
7. **점수–글 일치**: 5.8을 주고 칭찬만 하는 글이면 고친다.

### 2-7. 조판
기사를 쪽 단위 블록으로 바꿔 호 JSON을 만든다(4장 참고). 부록 싱글을 고른다.

- 부록 싱글 = 기사에서 이름이 나온 곡만. 리뷰마다 짚은 곡 1~2곡 + 샘플 원곡(Cypher) + 특집 곡.
- 9~12곡. 순서 = 기사에 나온 순서.

### 2-8. 발행과 기억
- `POST /api/mag/issues` → 앱에 새 호(비닐).
- 편집부 기억에 남김: 다룬 앨범·점수·평론가·쓴 비유 목록·예고("다음 호에서 ○○를 다룬다").
- 다음 호 편성 때 예고한 것이 있으면 우선 넣는다.

## 3. 잡지별 심층 코너

### Drop (금요일 신곡 · 보수적인 하드 리스너)
- **이번 주 필청 / 이번 주 리뷰**: 메인 1. 트랙별 메모 포함.
- **단평 6**: 앨범마다 점수와 한 문단.
- **원본을 들어라**: 이번 주 신보가 기대고 있는 옛 앨범 한 장(같은 프로듀서, 같은 장르의 원류). 편집부 취향이 가장 잘 드러나는 코너.
- **이번 주 실망**: 기대와 결과의 차이를 짧게. 점수 5.0 미만에서만.
- 매년 12월 첫 호: 올해의 앨범 20(그해 점수 기록에서).

### feedback (월요일 밴드 · 낭만주의자)
- **커버 스토리**: 밴드 한 팀의 이야기 3,000자 안팎. 결성 → 지난 앨범들 → 이번 판 → 이 밴드가 지키는 것. 아티스트 발언(요약) 중심.
- **이 판과 어울리는 밤**: 장면 글. 시간·날씨·장소를 정하고 그 장면 안에서 곡 세 개를 짚는다.
- **신인 세 팀**: 첫 EP·첫 앨범. 팀마다 출신, 결성, 들을 곡 하나.
- **공연 소식**: 웹에서 확인된 내한·투어만.

### Cypher (수요일 힙합 · 웹진 평론)
- **앨범 리뷰 2~3**: 가사·주제 / 랩 / 프로덕션 / 총평 항목별.
- **피처링 지도**: 이번 주 앨범들의 트랙 아티스트를 이은 관계도(데이터에서 자동). 겹치는 사람을 찾아 짧게 해설.
- **샘플 추적**: 샘플 원곡과 새 곡을 짝지어 소개. 원곡도 부록 싱글로.
- **씬 리포트**: 국내 힙합 한 꼭지(같은 주 국내 신보·소식).
- **가사 주제 분석**: 인용 없이 주제만 분류(예: 성공담 · 고향 · 관계 · 업계 비판). 비율 막대.

### 33⅓ (월간 · 내 청취 · 차트 데스크)
- **이달의 차트 Top 20**: 재생 수, ▲▼, NEW, 차트 개월 수.
- **차트 해설**: 1위 기사 + 큰 변동 3건.
- **장르 지형**: 장르 비율 변화(지난달 대비).
- **언제 듣나**: 요일×시간대 청취 히트맵, 가장 많이 들은 시간대와 그때의 곡.
- **편집부 vs 나**: 이달 주간지 점수와 독자 점수 차이가 큰 판 3장.
- **발견**: 처음 들은 아티스트 중 가장 많이 들은 셋.
- **잼 일지**: 잼 셋리스트, 펭귄 p가 넘긴 곡.
- 첫 달처럼 기록이 모자라면 "기록 n일치"를 표지와 차트 위에 밝힌다.

## 5. 실행 구조

```
[Worker cron 월·수·금 00:00, 매달 1일 00:00]
   └ 신보·앨범·아티스트 재료 → D1 mag_raw
[Claude 예약 작업 월·수·금 07:10, 매달 1일 07:10]  (새 세션, 지시문 = 이 문서 + personas.md)
   1 편성 → 2 취재 → 3 논점 → 4 점수 → 5 초고 → 6 검수 → 7 조판 → 8 발행
   └ 단계마다 /api/mag/drafts 에 저장 (끊기면 다음 세션이 이어서)
[앱]
   └ 새 호 → 비닐 → 읽기 → 부록 싱글 재생 → 출판사 크레이트
```

- 세션이 길어지면 단계 결과만 남기고 다음 단계로 간다(앞 단계 원문을 다시 읽지 않음).
