# 잡지 편집 로직 (심층 기사용)

음악 잡지 4권(Drop · feedback · Cypher · 33⅓)의 기사를 Claude가 직접 쓰는 방식의 설계.
목표는 "그럴듯한 글"이 아니라 **취재한 사실 위에 일관된 시각으로 쓴 깊은 글**이다.
잡지마다의 성격과 철학은 `mags/<잡지>.md`(바이블), 요약은 `personas.md`, 로고는 `logo-prompts.md`, 화면은 `stitch-prompts.md`.
이 문서에서 "바이블의 ○○"라고 하면 그 잡지 바이블의 같은 이름 항목을 그대로 가져다 쓴다는 뜻이다. 바이블과 이 문서가 다르면 사실 규칙(0장)은 이 문서가, 취향·말투·점수는 바이블이 우선한다.

---

## 0. 원칙

1. **Claude는 음악을 듣지 못한다.** 그래서 사실과 판단을 나눈다.
   - 사실: 출처가 있어야 쓴다(발매일, 크레딧, 녹음 과정, 아티스트 발언, 평단 반응).
   - 해석: 사실 두 개 이상을 이어서 끌어낸 것. 근거 사실을 가리켜야 한다.
   - 의견: 편집부 성격이 내리는 판단. 근거가 된 해석을 가리켜야 한다.
2. **소리 묘사는 증언으로만.** "기타가 날카롭다" 같은 문장은 출처 두 곳 이상이 같은 말을 할 때만 쓴다. 한 곳뿐이면 "~라고 프로듀서는 말했다"처럼 출처를 밝힌다.
3. **지어내지 않는다.** 기록에 없는 숫자·순위·인용·일화는 쓰지 않는다. 모자라면 분량을 줄인다.
4. **가사 인용 0줄.** 다른 매체 문장도 옮기지 않는다(직접 인용은 아티스트 발언 한 문장, 출처와 함께만).
5. **성격은 시각이지 거짓말 면허가 아니다.** 깐깐한 평론가도 사실은 똑같이 지킨다.

## 1. 재료 (데이터 계층)

| 층 | 무엇 | 어디서 | 언제 |
|---|---|---|---|
| 신보 목록 | 그 주 앨범, 장르별 | Spotify 검색 `tag:new` + 장르 필터 (Worker, Client Credentials) | 월·수·금 0시(KST) cron |
| 앨범 기본 | 트랙·길이·레이블·℗ 표기·발매일·트랙 아티스트(피처링) | Spotify `/albums/{id}` | cron |
| 아티스트 경력 | 지난 앨범 목록과 날짜, 장르, 사진 | Spotify `/artists/{id}`, `/albums` | cron |
| 크레딧 | 프로듀서·엔지니어·연주자·녹음 장소 | MusicBrainz API(무료, 키 없음, 초당 1회), 레이블 보도자료 | 편집 세션 |
| 배경 | 인터뷰, 녹음 과정, 앨범 소개 | 웹 검색 (매체 기사, 위키백과, 아티스트 SNS 공지) | 편집 세션 |
| 평단 반응 | 다른 매체의 평가 경향 | 웹 검색 (요약만, 문장 옮기기 금지) | 편집 세션 |
| 샘플 원곡 | 힙합 샘플·인터폴레이션 | 웹 검색 (크레딧 표기, 샘플 데이터베이스) | Cypher 편집 세션 |
| 내 청취 | 재생 기록, 크레이트 들은 횟수 `p`, 독자 점수 | 앱이 올린 기록 (D1) | 매달 1일 |
| 편집부 기억 | 지난 호 기사·점수·쓴 비유·예고 | D1 `mag_archive` | 매 호 |

cron은 재료만 모은다. 글은 편집 세션(Claude 예약 작업)이 쓴다.

## 2. 한 호를 만드는 순서

한 호 = Claude 세션 하나. 단계마다 결과를 `/api/mag/drafts/<호 id>/<단계>`에 저장해서, 세션이 끊겨도 다음 세션이 이어 받는다.

### 2-1. 편성 회의
후보 앨범마다 점수를 매겨 지면을 나눈다.

```
편성점수 = a × 내 관련도      (내가 들은 아티스트·크레이트에 있는 아티스트·같은 장르를 자주 들음)
         + b × 화제성        (웹 검색 결과 수, 다룬 매체 수)
         + c × 취재 가능성   (1차 취재에서 찾은 출처 수)
         + d × 편집부 적합도 (바이블의 '좋아하는 것'과 맞으면 +, '의심하는 것'에 걸리면 반박 거리로 +, 둘 다 아니면 0)
         + e × 철학 가점      (아래 표)
```

가중치는 바이블의 철학에서 나온다.

| 잡지 | a 관련도 | b 화제성 | c 취재 | d 적합도 | e 철학 가점 | 지면 규칙 |
|---|---|---|---|---|---|---|
| Drop | .20 | .10 | .30 | .30 | .10 · 정전과 이어지는 판(같은 프로듀서·같은 원류) | '화제를 의심한다' 때문에 화제성 가중이 가장 낮다. 필청 후보가 8.0에 못 미칠 것 같으면 필청을 비운다 |
| feedback | .35 | .05 | .25 | .20 | .15 · 첫 EP·첫 앨범, 내가 자주 듣는 밴드 | 신인 세 팀은 편성점수와 별도로 뽑는다(출처 2곳 이상인 신인 중 위에서부터) |
| Cypher | .20 | .15 | .35 | .20 | .10 · 샘플 원곡이 확인된 판 | 국내 앨범 최소 1장. 국내 신보가 없으면 씬 리포트로 채운다. 해외만 3장 이상 연속이면 다음 호에 국내 가점 |
| 33⅓ | — | — | — | — | — | 편성 없음. 바이블의 코너 순서대로 |

- 이미 다룬 앨범은 뺀다(같은 아티스트는 3호 안에 다시 메인으로 쓰지 않음).
- 결과: 메인 1 (필청 또는 커버 스토리) · 리뷰 2~3 · 단평 4~6 · 특집 주제 1. 바이블의 '코너와 그 이유'에 없는 코너는 만들지 않는다.
- **특집 주제 찾기**: 이번 주 후보들 사이 공통점(같은 프로듀서, 같은 샘플, 같은 장르 흐름, 같은 날 나온 라이벌)을 찾고, 2개 이상 엮이면 특집으로 쓴다.

### 2-2. 취재
앨범마다 **취재 노트**를 만든다.

```json
{
  "album": "spotify:album:...",
  "facts": [
    { "id": "f1", "claim": "프로듀서는 ○○", "kind": "credit", "src": "https://...", "conf": "high" },
    { "id": "f2", "claim": "녹음은 6주, 시골 농장 스튜디오", "kind": "process", "src": "https://...", "conf": "med" }
  ],
  "sound": [
    { "claim": "드럼을 거의 안 쓴 앨범", "srcs": ["https://a", "https://b"] }
  ],
  "said": [ { "who": "아티스트", "gist": "이번엔 라이브 한 번에 녹음하고 싶었다", "src": "https://..." } ],
  "reception": { "summary": "대체로 호평, 길이 지적 다수", "srcs": ["..."] },
  "career": { "prev": ["전작 (2022)", "전전작 (2019)"], "change": "전작보다 소리가 작아짐" },
  "samples": [ { "track": "곡", "from": "원곡 — 아티스트 (연도)", "src": "..." } ],
  "gaps": ["녹음 장소 미확인"]
}
```

- 출처 하한: 메인 리뷰 5곳 이상(서로 다른 곳), 리뷰 3곳, 단평 2곳. 못 채우면 한 단계 내린다(메인 → 리뷰 → 단평 → 제외).
- `kind`: credit · release · process · said · reception · chart · sample.
- `conf`: high(공식·1차 출처) · med(믿을 만한 매체) · low(커뮤니티). low만 있는 사실은 쓰지 않는다.
- 검색 예산: 메인 15회, 리뷰 8회, 단평 3회. 넘으면 있는 재료로 쓴다.

바이블의 철학 때문에 잡지마다 반드시 채워야 하는 칸이 있다. 메인 글에서 못 채우면 리뷰로 내린다.

| 잡지 | 필수 칸 | 바이블 근거 |
|---|---|---|
| Drop | `career.prev`(전작), `origin`(이 판이 기대는 과거 판 1장과 근거), 곡 순서·총 길이 | 원본을 안다 · 앨범은 하나의 작품 · 절제가 기술 |
| feedback | `story`(결성 연도·도시·멤버 변화), `together`(멤버가 함께 낸 순간에 대한 출처: 라이브 녹음 여부, 인터뷰) | 이야기를 존중한다 · 밴드는 한 방의 소리 |
| Cypher | `producers`(곡별 프로듀서), `samples`(확인된 것만), `career.place`(경력 속 자리), `scene`(같은 시기 흐름) | 프로덕션은 대화 · 맥락이 절반 |
| 33⅓ | 재생 기록 기간(일 수), 지난달 차트 | 기록이 기사다 · 측정 규칙 |

### 2-3. 논점 잡기
글마다 쓰기 전에 **설계도**를 만든다.

```json
{
  "thesis": "한 문장 주장",
  "because": [ { "point": "근거 1", "facts": ["f1", "f3"] }, { "point": "근거 2", "facts": ["f2"] }, { "point": "근거 3", "facts": ["s1"] } ],
  "counter": "가장 강한 반론과 그에 대한 편집부 답",
  "context": "전작·장르·같은 주 다른 앨범과의 관계",
  "moments": ["짚을 곡 2~3개와 이유"],
  "verdict": "결론 한 줄",
  "philosophy": [
    { "rule": "바이블 '핵심 철학' 표의 한 줄", "how": "이 글에서 그것을 어떻게 지키는가", "where": "몇째 문단" }
  ],
  "canon": "비교할 정전 앨범(있으면)과 이유",
  "critic": "필진 이름 (바이블의 '필진')"
}
```

- 근거 3개가 사실에 연결되지 않으면 쓰지 않는다.
- 반론을 반드시 하나 다룬다(심층 글과 감상문의 차이).
- `philosophy`에는 바이블 '핵심 철학' 표의 모든 줄이 들어가야 한다. 지킬 수 없는 줄이 있으면 그 이유를 적고, 메인이면 리뷰로 내린다.
- 정전 사용: 정전은 비교의 기준점이다. Drop은 리뷰마다 정전 또는 원류 1장을 반드시 짚는다. feedback은 깎아내리는 비교에 쓰지 않는다. Cypher는 국내 판을 해외 정전의 아류로 부르지 않는다. 33⅓은 정전이 없다.
- 필진 배정: 메인은 그 잡지 편집장, 단평·신인·씬 리포트는 바이블이 정한 데스크. 필진의 버릇(바이블)을 글에 한 번 드러낸다.

### 2-4. 점수
바이블의 '점수 철학' 기준표를 그대로 쓴다. 순서:

1. **하위 점수:** 기준마다 0~10으로 매긴다. 기준표의 기준점 설명(10 / 5 / 0)에 맞춰 근거 사실 id를 붙인다. 근거 없는 하위 점수는 5로 둔다.
2. **가중 합:** 바이블 비중으로 합한다. 각 잡지 척도로 바꾼다(Drop 0.0~10.0 · feedback 1~11 · Cypher 0.5 단위 별).
3. **성격 보정:** 바이블 규칙대로.
   - **Drop:** 최근 20개 평균이 6.0~6.9를 벗어나면 반대 방향으로 0.1~0.3 당긴다. 8.0 이상은 최근 10개 중 1개까지만 준다. 넘치면 7.9로 내리고 그 사실을 점수 근거에 적는다.
   - **feedback:** 신인은 +1. 11은 한 해 한 번(편집부 기억에서 확인). 4 이하가 나오면 다루지 않는다.
   - **Cypher:** 별 1 이하는 다루지 않는다. 같은 아티스트 지난 별점과 반 개 이상 차이 나면 이유를 쓴다.
   - **33⅓:** 점수 없음. 측정 규칙으로 순위만 낸다.
4. **금지된 입력:** 화제성·재생 수·다른 매체 점수는 하위 점수에 넣지 않는다(Drop·Cypher 레드라인). 편성점수에는 쓰되 점수에는 쓰지 않는다.

- 점수 근거 메모(하위 점수와 한 줄 이유)를 함께 저장. 화면에서 "점수 근거" 펼치기로 보인다.
- **필진 장부**: 평론가마다 지난 점수를 기억한다. 같은 아티스트 전작 점수가 있으면 글 안에서 그 차이를 설명해야 한다("이 지면은 전작에 6.4를 줬다. 이번엔…").

### 2-5. 초고
바이블의 '문체 규칙' + 설계도로 쓴다. 글 순서는 바이블마다 정해진 뼈대를 따른다(Drop: 첫 장면 → 의도 → 잘된 것 → 문제 → 반론 → 판정 / feedback: 장면 → 밴드 이야기 → 곡 속 순간 → 아쉬움 → 장면 / Cypher: 소개 → 가사와 주제 → 랩 → 프로덕션 → 총평 / 33⅓: 결론 → 숫자 → 흐름). 분량 목표:

| 글 | 분량 |
|---|---|
| 메인 리뷰 / 커버 스토리 | 2,000~3,500자 |
| 리뷰 | 1,000~1,500자 |
| 단평 | 250~400자 |
| 특집 | 1,500~2,500자 |

글 안 블록: 리드 문단 · 본문 · 풀쿼트(편집부 자신의 문장) · 팩트 박스(발매·레이블·프로듀서·길이) · 트랙별 짧은 메모(메인만) · 점수 박스 · 출처.

### 2-6. 데스크 검수 (따로 한 번 더)
초고를 쓴 뒤, 같은 세션에서 **검수자 역할로** 다시 읽는다. 고친 내역은 `desk.json`에 남긴다.

1. **사실 대조**: 문장의 고유명사·숫자·날짜를 모두 취재 노트와 맞춘다. 노트에 없으면 지운다.
2. **소리 검사**: 소리를 묘사한 문장마다 `sound`의 출처가 있는가. 없으면 지우거나 출처를 밝힌 문장으로 바꾼다.
3. **베끼기 검사**: 참고한 기사 문장과 연속 8어절 이상 겹치면 다시 쓴다.
4. **가사 검사**: 가사로 보이는 따옴표 구절이 있으면 지운다.
5. **말투 검사**: 바이블 금지어, 지난 4호에 쓴 비유 반복(편집부 기억과 대조).
6. **반론 검사**: 반론 문단이 있는가.
7. **점수–글 일치**: 5.8을 주고 칭찬만 하는 글이면 고친다.
8. **철학 검사**: 설계도의 `philosophy` 줄마다 글에서 실제로 지켰는지 문단을 찾아 확인한다. 못 지킨 줄이 있으면 고친다.
9. **레드라인 검사**: 바이블 '레드라인'을 한 줄씩 대조한다. 하나라도 걸리면 그 문단을 지운다. 이 검사는 고쳐 쓰기보다 지우기가 먼저다.
10. **문체 규칙 검사 (잡지별):**

| 잡지 | 확인할 것 |
|---|---|
| Drop | 첫 문단이 구체적인 것(표지·첫 곡·제목)에서 시작 · 마지막 문단에 판정 · 칭찬 표현은 한 번 · 50분 넘는 판이면 '뺄 곡' 언급 · 정전이나 원류 1장 언급 |
| feedback | 장면으로 시작하고 장면으로 닫음 · 계절·시간대·날씨 하나 이상 · '당신'은 한 번까지 · 상상한 장면이 상상임을 드러냄 · '이럴 때 들을 것' 있음 |
| Cypher | 앨범 [대괄호]·곡 '작은따옴표' · 소제목 5개 · 전문 용어는 처음에 풀어 씀 · "랩을 잘한다" 같은 뭉뚱그린 문장 없음 · 국내 판 최소 1장(호 단위) |
| 33⅓ | 문장마다 숫자 하나 이상 · 평가 형용사 없음 · 추측은 "기록상"으로 시작하고 기록으로 확인됨 · 기록 기간 표시 |

### 2-7. 조판
기사를 쪽 단위 블록으로 바꿔 호 JSON을 만든다(4장 참고). 부록 싱글을 고른다.

- 부록 싱글 = 기사에서 이름이 나온 곡만. 리뷰마다 짚은 곡 1~2곡 + 샘플 원곡(Cypher) + 특집 곡.
- 9~12곡. 순서 = 기사에 나온 순서.

### 2-8. 발행과 기억
- `POST /api/mag/issues` → 앱에 새 호(비닐).
- 편집부 기억에 남김: 다룬 앨범·점수·평론가·쓴 비유 목록·예고("다음 호에서 ○○를 다룬다").
- 다음 호 편성 때 예고한 것이 있으면 우선 넣는다.
- 바이블의 '성장 규칙'도 기억에 남긴다.
  - **Drop:** 12월 결산용 그해 점수, 정전 개정 이력(연 1회)
  - **feedback:** 내가 자주 듣는 밴드, 신인으로 소개한 밴드와 날짜(첫 앨범이 나오면 이어 쓴다), 11을 준 해
  - **Cypher:** 아티스트별 별점 이력, 피처링 지도 누적(자주 나오는 사람 → 다음 기획 후보), 국내/해외 비율
  - **33⅓:** 월별 차트(1월호 연간 Top 50용), 차트 개월 수(12개월 넘으면 '스테디')

### 2-9. 로고 쓰는 규칙
로고는 `logo-prompts.md`의 네 버전(① 제호 ② 줄임 마크 ③ 작은 아이콘 ④ 출판사 각인)을 쓴다. 편집 세션은 호 JSON의 `brand`에 어떤 버전과 색을 쓸지 적고, 앱이 그대로 그린다.

| 자리 | 버전 | 규칙 |
|---|---|---|
| 표지 | ① 제호 | 기본은 대표색. 단색(검정) 제호는 특별호에만 쓴다: Drop 12월 결산, 33⅓ 1월 연간호, feedback 11점을 준 호, Cypher 4.5 이상 별점이 나온 호 |
| 크레이트 앞판·책등 | ② 줄임 마크 | 스텐실(단색). 잡지 색은 책등에만 |
| 가판대·알림 | ③ 작은 아이콘 | '새 호' 표시와 함께 |
| 판권·부록 쪽 하단 | ④ 출판사 각인 | 호 번호, 날짜, '편집 노트' 숫자와 함께 |

- 로고 안에 기사 문구를 넣지 않는다. 표지 문구는 제호와 겹치지 않게 둔다.
- 호 사이에 로고 모양은 바뀌지 않는다. 바뀌는 것은 색 버전뿐이다(바이블의 '성장 규칙'과 같은 원리: 정체성은 고정, 기록만 쌓임).

## 3. 잡지별 심층 코너

### Drop (금요일 신곡 · 보수적인 하드 리스너)
- **이번 주 필청 / 이번 주 리뷰**: 메인 1. 트랙별 메모 포함.
- **단평 6**: 앨범마다 점수와 한 문단.
- **원본을 들어라**: 이번 주 신보가 기대고 있는 옛 앨범 한 장(같은 프로듀서, 같은 장르의 원류). 편집부 취향이 가장 잘 드러나는 코너.
- **이번 주 실망**: 기대와 결과의 차이를 짧게. 점수 5.0 미만에서만.
- 매년 12월 첫 호: 올해의 앨범 20(그해 점수 기록에서).

### feedback (월요일 밴드 · 낭만주의자)
- **커버 스토리**: 밴드 한 팀의 이야기 3,000자 안팎. 결성 → 지난 앨범들 → 이번 판 → 이 밴드가 지키는 것. 아티스트 발언(요약) 중심.
- **이 판과 어울리는 밤**: 장면 글. 시간·날씨·장소를 정하고 그 장면 안에서 곡 세 개를 짚는다.
- **신인 세 팀**: 첫 EP·첫 앨범. 팀마다 출신, 결성, 들을 곡 하나.
- **공연 소식**: 웹에서 확인된 내한·투어만.

### Cypher (수요일 힙합 · 웹진 평론)
- **앨범 리뷰 2~3**: 가사·주제 / 랩 / 프로덕션 / 총평 항목별.
- **피처링 지도**: 이번 주 앨범들의 트랙 아티스트를 이은 관계도(데이터에서 자동). 겹치는 사람을 찾아 짧게 해설.
- **샘플 추적**: 샘플 원곡과 새 곡을 짝지어 소개. 원곡도 부록 싱글로.
- **씬 리포트**: 국내 힙합 한 꼭지(같은 주 국내 신보·소식).
- **가사 주제 분석**: 인용 없이 주제만 분류(예: 성공담 · 고향 · 관계 · 업계 비판). 비율 막대.

### 33⅓ (월간 · 내 청취 · 차트 데스크)
- **이달의 차트 Top 20**: 재생 수, ▲▼, NEW, 차트 개월 수.
- **차트 해설**: 1위 기사 + 큰 변동 3건.
- **장르 지형**: 장르 비율 변화(지난달 대비).
- **언제 듣나**: 요일×시간대 청취 히트맵, 가장 많이 들은 시간대와 그때의 곡.
- **편집부 vs 나**: 이달 주간지 점수와 독자 점수 차이가 큰 판 3장.
- **발견**: 처음 들은 아티스트 중 가장 많이 들은 셋.
- **잼 일지**: 잼 셋리스트, 펭귄 p가 넘긴 곡.
- 첫 달처럼 기록이 모자라면 "기록 n일치"를 표지와 차트 위에 밝힌다.

## 5. 실행 구조

```
[Worker cron 월·수·금 00:00, 매달 1일 00:00]
   └ 신보·앨범·아티스트 재료 → D1 mag_raw
[Claude 예약 작업 월·수·금 07:10, 매달 1일 07:10]  (새 세션, 지시문 = 이 문서 + personas.md)
   1 편성 → 2 취재 → 3 논점 → 4 점수 → 5 초고 → 6 검수 → 7 조판 → 8 발행
   └ 단계마다 /api/mag/drafts 에 저장 (끊기면 다음 세션이 이어서)
[앱]
   └ 새 호 → 비닐 → 읽기 → 부록 싱글 재생 → 출판사 크레이트
```

- 세션이 길어지면 단계 결과만 남기고 다음 단계로 간다(앞 단계 원문을 다시 읽지 않음).
- 마감: 발행 시각이 지나도 메인이 안 끝나면 단평·차트만 먼저 발행하고, 메인은 "편집 중"으로 둔 뒤 다음 세션이 채운다.
- 실패 기록: 취재 부족으로 뺀 앨범, 지운 문장 수를 `desk`에 남겨 화면 맨 끝 '편집 노트'로 보인다.
