# 알리미 리마인더

사용자가 특정 시각에 무언가를 알려 달라고 하거나("~시에 알려줘", "~분 뒤에 말해줘",
"매주 월요일 9시에 ~"), 등록된 리마인더를 보여 달라거나 취소해 달라고 할 때 사용한다.
`cron` 도구로만 예약한다. exec sleep 등으로 흉내 내지 않는다.

## 기본 규칙

- 사용자 시간대는 **Asia/Seoul (UTC+09:00)** 이다. 현재 시각이 필요하면 `session_status`로 확인한다.
- 작업 이름은 반드시 `리마인더: <내용>` 형식으로 짓는다. 아침 브리핑이 이 접두어로 오늘의 리마인더를 찾는다.
- 전달 대상은 항상 텔레그램 `{{TELEGRAM_USER_ID}}` 이다.
- 날짜·시각이 모호하면(예: "3시" → 오전/오후 불분명, 이미 지난 시각) 등록 전에 한 번 되묻는다.
- 등록 후에는 `10월 10일 (금) 15:00에 "병원 예약" 알려드릴게요.`처럼 한 줄로 확인해 준다.

## 한 번만 알리는 리마인더

`cron` 도구 `action: "add"`, `job`:

```json
{
  "name": "리마인더: 병원 예약",
  "schedule": { "kind": "at", "at": "2026-10-10T15:00:00+09:00" },
  "sessionTarget": "isolated",
  "payload": {
    "kind": "agentTurn",
    "message": "다음 문장만 그대로 출력하고 다른 말은 덧붙이지 마: ⏰ 리마인더: 병원 예약",
    "thinking": "off",
    "timeoutSeconds": 120
  },
  "delivery": { "mode": "announce", "channel": "telegram", "to": "{{TELEGRAM_USER_ID}}" },
  "deleteAfterRun": true
}
```

- `at`에는 반드시 `+09:00` 오프셋을 붙인다. 오프셋이 없으면 UTC로 처리되어 9시간 어긋난다.
- "20분 뒤"처럼 상대 시간이면 현재 시각에 더해 절대 시각으로 바꿔서 넣는다.

## 반복 리마인더

`schedule`만 cron 식으로 바꾸고 `deleteAfterRun`은 뺀다. 시각은 한국 시각 그대로 쓰고 UTC로 바꾸지 않는다.

```json
{ "kind": "cron", "expr": "0 9 * * 1", "tz": "Asia/Seoul" }
```

예시: 매일 08:00 → `0 8 * * *`, 평일 22:00 → `0 22 * * 1-5`, 매월 1일 10:00 → `0 10 1 * *`.

## 조회 / 취소 / 변경

- 조회: `action: "list"` 후 이름이 `리마인더:`로 시작하는 작업만 다음 실행 시각 순으로 보여 준다.
- 취소: 목록에서 해당 작업을 찾아 `action: "remove"`, `jobId`. 여러 개가 맞으면 어느 것인지 되묻는다.
- 시각 변경: `action: "update"`, `jobId`, `patch: { "schedule": { ... } }`.

`리마인더:` 접두어가 없는 작업(예: `알리미: 아침 브리핑`, `알리미: 일정 사전 알림`)은
사용자가 이름을 콕 집어 요청하지 않는 한 수정하거나 삭제하지 않는다.
